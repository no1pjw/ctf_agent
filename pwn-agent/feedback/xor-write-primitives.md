# XOR 제한 쓰기 primitive

## 같은 PIE 페이지의 포인터 전환

- **증상:** 인덱스 검증이 없는 `qword` XOR 연산으로 배열 밖의 쓰기 가능한 함수 포인터에 접근할 수 있지만, 임의 값을 직접 대입하거나 PIE base를 누출할 수는 없다.
- **재사용 가능한 교훈:** 기존 콜백과 목표 함수가 같은 PIE 페이지에 있으면 로드 base가 페이지 정렬되어 더해진 뒤에도 두 포인터의 XOR 차이는 page offset 비트에만 남는다. 따라서 `old ^ target`을 만들 수 있는 입력 값들이 있으면 주소 누출 없이 콜백을 목표 함수로 전환할 수 있다. 종료 시 호출되는 `.fini_array`는 종료 동작을 trigger로 쓸 수 있는 후보이며, 해당 엔트리가 실제로 쓰기 가능한지는 RELRO와 런타임 매핑을 함께 확인해야 한다.
- **가장 싼 확인법:** ELF에서 배열과 후보 포인터의 상대 거리가 원소 크기로 정확히 나누어지는지, 원래 콜백과 목표 함수의 페이지 번호가 같은지, 그리고 필요한 XOR delta의 각 비트를 입력 값들의 XOR 조합으로 만들 수 있는지 정적으로 계산한다. solver도 심볼·섹션 값에서 이 계획을 산출하고 정렬 및 동일 페이지 조건을 assert하게 한다.
- **환경/적용 한계:** 서로 다른 PIE 페이지이면 base 덧셈의 carry 때문에 단순 XOR delta가 ASLR 불변이라고 볼 수 없다. 포인터 인증, CFI/CET의 간접 분기 제약, 읽기 전용 relocation 영역, 초기 값 차이도 별도 확인한다. 가능한 경우 XOR 항 하나를 생략한 음성 대조군으로 성공이 우연한 종료 동작이 아님을 검증한다.

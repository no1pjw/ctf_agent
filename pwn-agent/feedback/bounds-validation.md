# Bounds validation lessons

## 스케일된 signed index의 modular alias

- **증상:** 배열 접근이 상한만 검사하고 음수 인덱스를 허용하며, 주소를 `base + stride * index` 형태의 고정 폭 정수 연산으로 만든다.
- **재사용 가능한 교훈:** 단순한 작은 음수뿐 아니라 `stride * index`가 정수 폭에서 wrap되어 정상 슬롯이나 그 인접 영역과 같은 변위를 만드는 큰 음수도 후보가 된다. 따라서 디컴파일러의 배열 표기만 보고 접근 가능 범위를 판단하지 않는다.
- **가장 싼 확인법:** 인덱스의 파싱 폭·signedness, 실제 곱셈 폭, stride를 확인한 뒤 모듈러 식 `stride * index mod 2^word_size`만 계산해 목표 슬롯과의 별칭을 정적으로 검사한다.
- **환경/적용 한계:** 컴파일된 기계어가 wrap되는 고정 폭 연산을 실제로 사용해야 한다. 컴파일러가 overflow 불가능성을 가정해 최적화했거나 checked arithmetic, 하한 검사, 더 넓은 중간값을 쓰면 같은 결론을 적용할 수 없다.

## 거부 전에 발생하는 입력 부작용

- **증상:** 프로그램이 `scanf` 같은 입력 함수로 값을 목적지에 먼저 저장한 뒤 범위를 검사하고, 실패 시 오류만 출력하고 계속 실행한다.
- **재사용 가능한 교훈:** 해당 작업이 최종적으로 거부돼도 목적지 쓰기는 이미 발생했다. 목적지가 다른 객체와 alias되거나 OOB 주소 계산으로 선택될 수 있다면, 실패 경로 자체가 제한된 값 쓰기 primitive가 된다.
- **가장 싼 확인법:** 소스나 짧은 disassembly에서 `parse/store -> compare -> reject` 순서를 확인하고, 거부 경로가 저장값을 복원하거나 프로세스를 종료하는지도 함께 본다. 가장 가까운 비중요 필드의 변경 여부를 음성 대조군으로 확인한다.
- **환경/적용 한계:** 파서가 변환에 성공해야 하며 목적지 타입과 표현 범위를 지켜야 한다. 거부 경로가 즉시 비복귀 종료하거나 값을 복원하고, 변경된 객체가 그 전에 소비되지 않으면 exploit primitive가 되지 않는다.

## 실패한 상태 전이의 부분 커밋을 추적한다

- **증상:** 잔액·수량·quota를 옮기는 작업이 실패를 반환하지만, 이후 조회에서 한쪽 값이 계속 증가하거나 감소한다.
- **재사용 가능한 교훈:** 검증 전에 여러 필드를 갱신하고 실패 시 전부 롤백하지 않으면, 거부된 작업의 반복만으로 논리 크기와 실제 allocation 같은 불변식을 깨뜨릴 수 있다. 오류 메시지를 종료점으로 보지 말고 성공·실패 양쪽의 모든 쓰기와 보상 동작을 대조한다.
- **가장 싼 확인법:** 중요하지 않은 두 객체로 반드시 실패하는 작업을 한 번 수행하고, 직전·직후의 양쪽 필드를 조회한다. 소스가 있으면 `write -> check -> reject` 경로에서 역연산이나 원본 복원이 빠졌는지 확인한다.
- **환경/적용 한계:** 변경값이 실패 뒤에도 보존되고 후속 메모리 크기·권한·경제 로직에 사용되어야 한다. 트랜잭션 롤백, 복사본 커밋, 재조회 시 재계산이 있으면 적용되지 않는다.

## 재할당 뒤 논리 크기와 실제 크기를 다시 대조한다

- **증상:** 크기 변환 후 기존 버퍼를 해제하고 새 버퍼를 할당하지만, 별도 길이 테이블은 이전 값을 유지하며 후속 읽기·쓰기가 그 값을 신뢰한다.
- **재사용 가능한 교훈:** 고정 폭 shift·곱셈이 wrap되어 실제 allocation이 최소 크기로 축소되면, stale한 논리 크기와 실제 chunk 크기의 차이가 곧 인접 힙 read/write 범위가 될 수 있다. 산술 overflow만 찾고 끝내지 말고 포인터와 길이 메타데이터가 함께 갱신되는지 추적한다.
- **가장 싼 확인법:** 소스나 짧은 disassembly에서 `free -> 크기 계산 -> allocation -> 포인터 저장` 경로와 길이 필드 쓰기를 대조하고, 계산식은 피연산자와 결과의 실제 정수 폭에서 정적으로 평가한다.
- **환경/적용 한계:** allocator가 0 또는 작은 요청을 거부하거나 프로그램이 allocation 실패를 종료로 처리하면 같은 primitive가 생기지 않는다. 후속 접근이 실제 크기를 다시 검사하거나 길이 필드를 갱신해도 적용되지 않는다.

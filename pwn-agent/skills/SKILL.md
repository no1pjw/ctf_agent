# CTF Pwn

사용자에게 보이는 진행 상황, 판단, 오류 설명 및 최종 답변은 기본적으로 한국어로 작성한다. 명령어, 코드, 경로, 심볼 및 원문 진단 메시지는 정확성을 위해 원래 표기를 유지한다.

Read `../docs/HARD_RULES.md`, then `../docs/role.md` and `../docs/playbook.md`. Read the active challenge ledger and `../../rules/ruleset.md`.

1. Preserve inputs without calculating checksums; complete P0-Lite and treat category routing as fixed when invoked by `ctf-pwn`.
2. Before triage, read `work/runtime/runtime.env`, prepared by `../../references/tools/pwn-runtime-prepare.sh`. Prefer a supplied libc/loader pair; when it is absent or incomplete, let the launcher complete it only from the exact challenge image. Use `libc_path` for libc symbol/offset calculations, and treat only `runtime_status=ready` as an exact local pair. Never substitute host libc or combine an unverified loader/libc pair. A partial or incompatible bundle does not block STATIC-ONLY analysis or a bounded official remote attempt.
3. Start with the bounded Fast Probe in `../docs/playbook.md`; read only `../feedback/index.md` initially and open a linked feedback file only when its symptoms match. Escalate in place only on explicit triggers.
4. Use `../../references/tools/pwn-triage.sh`, `pwn-gadget-index.sh`, `pwn-build.sh`, `pwn-run.sh`, and the pwntools template instead of rebuilding command logic. When control-flow reuse is relevant, define the exact required semantics first and run `pwn-gadget-index.sh <binary> work/cache` at most once for the main ELF. Reuse its Build-ID cache. Do not repeat broad gadget enumeration: if the first index confirms a pivot but lacks the required argument/control gadgets, record gadget scarcity and immediately switch to PLT/GOT call sites, indirect dispatch, leak/base design, ret2dlresolve, or another primitive justified by the binary. Search the supplied libc only after a leak or another concrete libc-base strategy exists, and keep its offsets separate from the local image libc.
   If neither a Dockerfile nor the named cached image exists, enter `STATIC-ONLY`: run static triage once, do not synthesize or pull an environment, do not retry Docker, and do not escalate solely for the missing Dockerfile. This forbids local target execution but does not block a bounded client-only attempt to an exact recorded official endpoint after static analysis completes a parameterized solver.
5. Prove primitives incrementally: reachability, control, leak, calculation, final effect.
6. Execute only through P4 inside Docker/sandbox or the exact official endpoint recorded in `scope/remote-target.env`. For a recorded remote target, use Fast-to-Remote as soon as the solver is ready: use one local exploit-derived flag when an exact local runtime exists; otherwise independently cross-check the primitive, offsets, addresses, and I/O framing statically, syntax-check the parameterized solver, and immediately run it through `../../references/tools/pwn-remote-run.sh`. A Dockerfile, cached image, or local flag is not a prerequisite when no local runtime exists. Do not wait for repeat runs, a negative control, P5, or the write-up.
7. If the first remote attempt fails, compare the runtime provenance and leak/base calculation first, then allow one more attempt only with a materially corrected exploit. If no remote endpoint is recorded, retain two clean local successes plus one negative control. Have P5 verify existing evidence without executing and never delay an already obtained remote flag.
8. In Fast mode write only `work/solve.py` and concise `work/writeup.md`; use detailed logs only for Deep/Audit or checkpoints.
9. After a flag is actually validated, write `verified` to `work/.solved`. Never mark an unverified hypothesis as solved. Workspace compaction may remove only recoverable duplicate inputs, audit logs, caches, core dumps, and regenerable runtime copies; it must preserve feedback, solver, write-up, scope, runtime provenance, and private flag evidence.
10. For heap, race, probabilistic, VM-like, or multi-stage exploits, use `../../references/tools/pwn-checkpoint.sh` after each decisive stage. Keep only stage, status, environment assumption, observed invariant, and cheapest next test; never store flags, secrets, full dumps, or repeated command logs. On restart or remote failure, read `work/state.json` and resume from the last passed stage instead of rebuilding the chain from memory.
11. Let the launcher remove containers derived from the challenge image and the exact `ctf-<challenge>:local` image on every normal, failed, or interrupted exit when a Dockerfile is supplied. Never perform broad Docker pruning. Preserve them only when the user invoked `--keep-docker`.

Return the primitive chain, exploit, environment, transcripts, controls, and reproduction steps. Make `solve.py` print `FLAG=<validated flag>` only after format and derivation validation, then close and exit immediately. When a remote run obtains it, immediately show both `획득한 플래그: <validated flag>` and `원격 플래그 획득 시간: N.NNN초` in the user-visible terminal and final answer; never delay them for P5 or replace them with only a file path. Store remote transcripts and candidate flags under `evidence/private/`, but do not put flag plaintext in the public write-up or submit it to a scoreboard. Never generalize an exploit to unrelated targets.
